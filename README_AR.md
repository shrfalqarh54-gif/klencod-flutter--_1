# مشروع إنجاز — Flutter

اسم الحزمة المعتمد: `com.injaz.app`

## ما يتضمنه المشروع
- مهام يومية مستقلة محفوظة محلياً.
- إضافة وتعديل وحذف المهام.
- نص المهمة متعدد الأسطر؛ زر Enter يضيف سطراً جديداً داخل المهمة.
- وقت بداية لكل مهمة.
- حالات: معلقة، تم، لم يتم.
- لون مستقل لكل مهمة.
- تكرار يومي اختياري؛ المهام غير المنجزة لا تنتقل تلقائياً.
- سجل الأيام السابقة.
- إحصائيات أسبوعية.
- نسبة الإنجاز وعدّاد المتبقي ورسالة إكمال.
- نسخ قائمة اليوم.
- الوضع الداكن.
- العربية والإنجليزية.
- تذكير محلي يومي بوقت يحدده المستخدم، مع إشعار منفصل لكل مهمة وزري «تم» و«لم يتم».
- يعمل دون حساب أو اتصال إنترنت.

## الإعداد
1. افتح مجلد المشروع في Klencod IDE.
2. نفّذ `flutter pub get`.
3. نفّذ `flutter analyze`.
4. جرّب `flutter build apk --debug` أولاً.
5. بعد نجاحه نفّذ `flutter build apk --release`.

## عناصر تركناها لتحديدك
- اسم التطبيق الذي يظهر تحت الأيقونة: غيّر القيمة المؤقتة `APP_NAME_HERE` في `android/app/src/main/AndroidManifest.xml`.
- أيقونة التطبيق: استبدل موارد launcher الافتراضية في `android/app/src/main/res/mipmap-*`.
- رقم الإصدار: غيّر القيمة المؤقتة `0.0.0+1` في `pubspec.yaml` إلى رقم الإصدار الذي تختاره.

لم نضع مفتاح API أو أي خدمة سحابية. التطبيق لا يحتاج إلى إنترنت لوظائفه.

## ملاحظات مهمة عن الإشعارات
- الإشعارات محلية ولا تحتاج إلى إنترنت.
- على Android 13+ يجب السماح بإذن الإشعارات.
- على Android 12+ قد يطلب النظام إذن المنبهات الدقيقة؛ إذا لم يمنحه المستخدم فقد يستخدم التطبيق جدولة غير دقيقة وقد يتأخر الإشعار.
- أزرار المهام تظهر كإشعارات مجمعة: إشعار لكل مهمة وزراه الخاصان، مع إشعار ملخص. هذا يتجنب حد أزرار الإشعار الواحد في Android.
- Android والشركات المصنّعة قد يقيّدون الإشعارات عند تفعيل توفير البطارية أو إيقاف التطبيق إجبارياً. لا يمكن ضمان منع المستخدم أو النظام من إزالة الإشعار في جميع الظروف.
- عند فتح التطبيق في يوم جديد، يُنشئ مهام التكرار اليومي ويعيد جدولة إشعارات اليوم. افتح التطبيق مرة واحدة في اليوم لضمان تحديث مهام اليوم وجدولتها؛ لا يمكن لتطبيق Flutter وحده تنفيذ منطق إنشاء يوم جديد في منتصف الليل إذا لم يُشغّل النظام التطبيق.
- هذه الحزمة لم يتم بناؤها فعلياً داخل بيئة Klencod؛ تقرير Klencod السابق لم يوفر طرفية Flutter CLI. لذلك اختبر `flutter pub get`, `flutter analyze`, ثم بناء debug قبل اعتماد APK النهائي.

## هيكل مختصر
- `lib/main.dart`: التطبيق، التخزين، الواجهات، والإشعارات.
- `android/`: إعداد Android وManifest.
- `.github/workflows/android.yml`: بناء APK على GitHub Actions.
